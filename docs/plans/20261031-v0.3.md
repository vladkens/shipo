# shipo v0.3: wavo on shipo, Windows signing

The open items of the v0.2 plan (docs/plans/completed/20261030-v0.2.md), after the v0.2.0 release on 2026-10-31.

## Tasks

- [ ] 1. The uninstaller's copy, `%TEMP%\<Name>-uninstall-<pid>.exe` (or the install folder's parent when %TEMP% is on another drive), is never deleted (`setup/src/windows.rs`, `uninstall_from`; found testing wavo's setup in the VM, not fixed in 0.2.0): it deletes itself after the uninstall, and the next run sweeps old copies.

- [ ] 2. Uninstall.exe's FileDescription is the setup's ("<Name> Setup"), so Task Manager and prompts call it that (found with 1): stamp "<Name> Uninstall".

- [ ] 3. The first wavo release on shipo is the proof with the real secrets (agreed 2026-10-30: no separate run): a wavo-app branch packs a release with shipo instead of pack.py (the person runs it, or adds the secrets to shipo); the DMG is notarized and stapled (`xcrun stapler validate`, `spctl -a -t open --context context:primary-signature`, a quarantined first launch in the macOS VM, a Finder shot of the mounted window read and compared with today's DMG), the setup installs and updates on Windows 11 in the VM, the AppImage and .deb run on Ubuntu.

- [ ] 4. Waiting for the person: the Start menu shortcut's AppUserModelID.

- [ ] 5. Authenticode for the setup, the uninstaller and the exe.

- [ ] 6. The setup stub built inside a pinned Docker image (Ubuntu, the exact Rust, cargo-xwin, the CRT and the SDK), so its bytes are the same on any host and CI's check of stubs/ runs on ubuntu.

- [ ] 7. A root Cargo workspace with the setup in it, so the setup shares `src/cli/payload.rs` and `src/uninstall.rs` as a crate, not by `#[path]`.

- [ ] 8. Later, from the other packagers' issues: a fallback for macOS volumes without the APFS swap; notarization resume and a configurable wait; the native-arch record under emulation; feed records for the app id, expiry and minimum OS; channels; URL schemes, file associations, resources and sidecars on demand; C bindings and a dylib/so of the updater for apps not in Rust.

After v1, in other repos and PRs: wavo-app moves onto shipo; nimbo drops `src/update.rs`, its platform code and `scripts/pack.py` (its `Png` and launcher stay); its `update::dialog` stays, over a small release type of its own (version, notes link), which the app fills from `shipo::Release`, so nimbo never depends on shipo.
